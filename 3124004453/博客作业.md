## 二、计算模块接口的设计与实现过程

### 2.1 整体架构

本项目采用模块化设计，将论文查重功能拆分为以下几个核心模块：

```
main.py                    # 主程序入口，处理命令行参数和文件IO
plagiarism_checker.py      # 核心查重算法模块
test_plagiarism_checker.py # 单元测试
requirements.txt           # 依赖声明
```

### 2.2 核心类与函数

项目以函数式编程为主，核心函数如下：

| 函数名 | 功能说明 |
| --- | --- |
| `clean_text(text)` | 文本预处理，去除标点符号和空白字符 |
| `segment_words(text)` | 中文分词，优先使用 jieba，不可用时退化为单字分词 |
| `get_char_ngrams(text, n)` | 生成字符级 n-gram 列表 |
| `cosine_similarity(vec1, vec2)` | 计算两个词频向量的余弦相似度 |
| `word_level_similarity(text1, text2)` | 词级相似度计算 |
| `ngram_level_similarity(text1, text2, n)` | n-gram 级相似度计算 |
| `calculate_similarity(orig_text, plag_text)` | 综合相似度计算（主接口） |

### 2.3 算法设计

本项目采用**词级余弦相似度 + 字符级 bigram 相似度**的加权融合算法：

1. **文本预处理**：去除所有标点符号、空白字符，统一转为小写，消除格式差异的干扰。

2. **词级相似度（权重 0.6）**：
   - 使用 jieba 对两篇文本进行精确模式分词
   - 统计各自的词频向量（Counter）
   - 计算两个向量的余弦相似度

3. **字符级 bigram 相似度（权重 0.4）**：
   - 将预处理后的文本切分为相邻字符对（bigram）
   - 统计 bigram 频率向量
   - 计算余弦相似度

4. **加权融合**：`最终重复率 = 0.6 × 词级相似度 + 0.4 × bigram 相似度`

### 2.4 算法独到之处

- **双维度融合**：词级相似度捕捉语义层面的重复，bigram 相似度捕捉字面层面的重复，两者互补，对增删改、语序调整等抄袭手段都有较好的检测能力。
- **优雅降级**：当 jieba 库不可用时，自动退化为单字分词，保证程序在任何环境下都能运行。
- **多编码兼容**：文件读取支持 UTF-8、GBK、GB2312、UTF-16 等多种编码，避免因编码问题导致测试失败。
- **边界保护**：对空文本、纯标点文本等边界情况做了完善处理，确保不会出现除零错误或异常退出。

### 3.3 性能瓶颈分析

从分析结果可以看出，消耗最大的函数依次为：

1. **`clean_text`（文本预处理）**：累计 0.020 秒，占总耗时约 43%。主要消耗在字符串遍历和 `join` 操作上。
2. **`cosine_similarity`（余弦相似度）**：累计 0.017 秒，占总耗时约 37%。主要消耗在向量点积和模长计算的 `sum` 操作上。
3. **`get_char_ngrams`（n-gram 生成）**：累计 0.013 秒，占总耗时约 28%。

### 3.4 改进思路与措施

**改进一：文本预处理优化**
- 原始实现使用生成器表达式逐字符判断，函数调用开销大。
- 改进：使用 `str.translate()` 配合翻译表进行批量字符删除，减少 Python 层循环。

**改进二：余弦相似度计算优化**
- 原始实现分别计算点积、模1、模2，需要遍历向量多次。
- 改进：在一次循环中同时累加点积和模长，减少遍历次数；使用 `math.sqrt` 而非 `**0.5`。

**改进三：避免重复预处理**
- 原始实现中 `word_level_similarity` 和 `ngram_level_similarity` 各自调用 `clean_text`，导致同一文本被预处理两次。
- 改进：在 `calculate_similarity` 中统一预处理一次，将结果传入各子函数。
